Aiko Chat — Pre-Submission Preflight

Run this before every App Store / Play submission, on every platform you're shipping. Companion to the Submission Kit (the kit is what you paste at the gate; this is what you verify before it). Every check below exists because it was a wall discovered at the submit gate during the 2026-07 launch — the whole point is to move each precondition earlier. The automated form of this belongs in the asc/gplay CLI (claude-tasks#15 / #14, ~/git/tools/cli-tools/appstore); until then, this is the documented manual gate.

The crux: distribution is artifact-grounded. The tooling encodes the happy path; every rejection came from a precondition that was true on main but not in the submitted artifact / live platform. Repo intent ≠ submitted reality — verify the reality.

The five checks

1 · The submitted build actually carries the intended fix + a fresh version

partly automatableall platformsAndroid worst-hit
Wall it prevents: version code +8 was reused across ~18 days of commits, so the fix merged to main (the passkey nudge, PR #101) was never in the submitted AAB. Google reviews the artifact, not main → two rejections on an already-fixed bug.
Verify: 
# version bumped since the last submitted build?
grep '^version:' pubspec.yaml            # e.g. 0.0.1+9  — the +N must be NEW
asc builds        | head -3              # iOS/macOS: is the latest build a fresh number?
gplay status --track production          # Android: which versionCode is live/submitted?

# the fix commit is actually in the build you're about to submit:
git log --oneline -1                     # HEAD you built from
# → confirm the intended fix SHA is an ancestor of the built commit
Rule: one build number per build. Never resubmit a reused version code expecting new code in it.

2 · Every metadata URL resolves 200

automatableall platforms
Wall it prevents: privacy / support / marketing URLs 404ing → rejection or a broken public listing. Canonical legal pages now live in the standalone nickmeinhold/aikochat repo, served at aikochat.org — decoupled from both the app release cadence and the island host (which is what let the old imagineering.cc URLs 404 during a migration).
Verify: 
for U in \
  "https://aikochat.org/privacy" \
  "https://aikochat.org/terms" \
  "https://aikochat.org/delete-account" \
  "$MARKETING_URL"; do
  echo "[$(curl -s -o /dev/null -w '%{http_code}' -L "$U")] $U"
done   # every line must be 200
Canonical: privacy = aikochat.org/privacy, terms = aikochat.org/terms, deletion = aikochat.org/delete-account (a real standalone page now — replaces the old privacy #retention anchor stopgap). Marketing URL = aikochat.org/ (optional field; the compliance landing doubles as it).

3 · The sole-ingress auth path (passkey) works on the target platform

manual gate (partly automatable)all platforms
Wall it prevents: passkey is the only way in — if it's broken on a platform, no one gets in, reviewer included. Android CREATE failed on every device because assetlinks.json was missing the handle_all_urls relation (while Google's own assetlinks:check stayed green — a lying proxy).
Verify (automatable part) — the well-known files carry the right relations: 
# Android: BOTH relations required (get_login_creds AND handle_all_urls)
curl -s https://chat.imagineering.cc/.well-known/assetlinks.json | \
  grep -o 'get_login_creds\|handle_all_urls' | sort -u   # must show BOTH

# Apple: AASA served for the associated domain
curl -s https://chat.imagineering.cc/.well-known/apple-app-site-association | head
Verify (manual gate): on the target platform, against prod, tap Create a passkey (never "Sign in" on a fresh device), authenticate, confirm you reach the chat. This is the single most-rejected path — see the Submission Kit's reviewer note.

4 · You know the account's submit capability (API vs Console-only)

documented constantdiffers per platform
Wall it prevents: a "submitted" that's silently a draft. This Play account has changesNotSentForReview — the API cannot auto-submit; a plain commit stages a draft that waits for a human Console click. iOS/macOS ASC reviewSubmissions does submit via API.
PlatformSubmit pathGate
iOS / macOSASC reviewSubmissions APIFully API (asc with --confirm)
AndroidPlay Console onlyHuman click: Publishing overview → "Send for review". API commit = draft only.
Rule: after a Play push, the job is not done until the Console "Send for review" is clicked and the change shows in review.

5 · Platform-required manifest / Info.plist keys are present

automatableplatform-specific
Wall it prevents: a missing platform key that only surfaces at the submit gate — LSApplicationCategoryType is a Mac App Store requirement (iOS doesn't need it) and was discovered at MAS submit time.
Verify: 
# macOS (MAS): app category REQUIRED
grep -A1 LSApplicationCategoryType macos/Runner/Info.plist

# iOS: skip the per-build encryption question
grep -A1 ITSAppUsesNonExemptEncryption ios/Runner/Info.plist

# Android: passkey relations (see check 3) + a bumped versionCode (see check 1)
