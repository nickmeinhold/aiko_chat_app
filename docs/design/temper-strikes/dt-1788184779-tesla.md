**Summary:** You designed the echo after the bell: nine gates, a Dart timer, and a preference — while the bell is a Swift handler with a payload too thin to prove anything, a ceiling that cannot survive suspension, and a user who can Answer before proof.

The universe here is not Dart. It is the PushKit handler, the CallKit UUID, and the one input that makes the glass sing: a second VoIP push, or a thumb on Answer, while `admitRing` is still a process that does not exist.

---

**Fatal flaws:**

- **Wrong option-frame at the load-bearing sentence (§4, one-sentence version).** "CallKit rings before Dart exists, therefore all nine refusals become post-hoc" is a fact about the Flutter engine, smuggled as a fact about the device. Swift is alive in `pushRegistry(_:didReceiveIncomingPushWith:completion:)`. Ed25519 verify is microseconds. The missing arm is: Swift admits from signed bytes plus App Group state (keys, mute, block, consent, `_ended`), and Dart maintains that cache the way §6 already maintains names. The document offers only (i) island-proof, (ii) ring-then-retract, (iii) island two-push-classes. That triad hides the one arm that keeps signed-at-birth on the handset. You heard Dart's silence and called it physics.

- **The deferral to design 12 is not safe, and the collision is unmarked (Design 16 §4 / §6 vs Design 12 Decision 4 / 6).** Design 12's payload is `c` plus, later, a call id — deliberately opaque so Apple is not told who calls whom. That payload cannot support a signature check, a signed `signedAtMs`, or a hangup-versus-invite dispatch. Design 16 then inherits "send-time correctness moves onto the island" as weather, without demanding the bytes Swift would need to keep the island untrusted. Opacity and on-device proof cannot both be true. One of the two documents has to give. Neither currently does.

- **No PushKit dispatch table for the end sentinel (Design 16 is silent; Design 12 Decision 5 is the island blocker).** Every VoIP push must talk to CallKit before the handler returns. Design 12 will wake the end sentinel as VoIP. If Swift reports that push as a *new* incoming call, every hangup is a second ring — the stop becomes a start. If Swift only `reportCall(endedAt:)` on the UUID, it is unverified whether Apple counts that as "reported." If the end is downgraded to alert so this problem vanishes, a locked ringing phone never hears the stop. This is the inverted failure arriving through the client handler, and it is not in the document that claims to own the client half.

- **§3's fork cannot re-establish the ceiling it took (Decision 1c, §3 a/b/c).** A CallKit incoming UI is system UI; the app is suspendable the instant the report completes. A Dart `Timer` does not run. A Swift `asyncAfter` / `Timer` does not reliably run either. Arm (c) is correctly dismissed (expiration bounds delivery, not a drawn ring). What remains is `beginBackgroundTask` racing an OS budget you do not own, plus Design 12's signed end-push. Maxwell's 30s pillar is not "taken"; it is gone. A crashed caller with no end still rings until a human or the OS stops it. Naming (b) as preference because "(a) drifts a constant" is rearranging two dead timers.

- **The ceiling, if it runs at all, is keyed off an unsigned field the island can lie about (§3 arm a: `signedAtMs + kCallRingDuration`).** `call_invite.dart:441` refuses island `createdAt` for this exact reason. Putting `signedAtMs` in APNs so Swift can expire the ring hands the island the loudest clock in the product, unsigned, unless the handler verifies the origin envelope first — which the payload cannot do (see opacity). Substitute `now + duration` and a week-old invite rings for a full window the moment it is delivered. That is the staleness bug with the sign flipped on, which §1 claims to be retiring.

- **CXAnswerCallAction is a trust decision the document does not contain (§4 sequence is ring → Dart → admitRing → end).** The reason CallKit exists is that a locked-device human can Answer. That action arrives in Swift before Dart exists, therefore before `admitRing`. Fulfill-then-refuse lands the user in a live audio session for a forged, muted, or blocked call. Fail-after-tap looks like a crash at the one moment the product promised to feel like a phone. "How fast to stop" is a ringing-state sentence. Answered-state is a different machine, and it is the one that fires at 3am.

- **CallKit UUID is an unsigned identity key (§6 + Design 12 Decision 1, unstated in Design 16).** Swift must report a UUID before proof. That UUID will come from the island's payload, not from the signed ULID. Payload ULID ≠ signed ULID ⇒ `reportCall(endedAt:)` cannot find the ringing call ⇒ hangup retention in §1 Site 2 is theatre. Payload reuse of a live UUID is identity-as-mutable-key: call N stops call N-1, or two invites collapse into one system call. The map *payload UUID ↔ signed ULID ↔ `_ended` key* is the client contract. It is not written.

- **Name cache plus Recents plus post-hoc refuse is spoofed caller-ID, not a #3695 footnote (§4 arm ii, §6, Design 12 Decision 6a).** Swift will paint the cached channel name on an unverified VoIP push, through DND, then `includesCallsInRecents = true` writes a missed call for a ring `admitRing` would have silenced. Harassment fills Recents as "Mom." The cache does not merely leak names on disk; it is the identity of a call that has not been admitted. Design 12 scoped Recents to "a call they were party to." Post-hoc refusal means they were not.

- **Arm (ii) under-counts blast radius all the way to Apple (§4, Open questions).** A `should_wake` hole, or a retraction that is not actually sub-second (listed as unmeasured), is not only one user getting a full-screen ring. It is a fleet-wide report-and-end ratio. Apple revokes VoIP for that. The feature's failure mode is losing the right to ring *anyone*. Design 12 Decision 7 priced harassment. Design 16 did not price revocation.

- **`kPushDeliverySlack` is a fourth clock pretending the three clocks collapsed (§1, Open questions).** Island 60, freshness 10, ring 30: collapse into "ring duration," then immediately invent slack, keep 17.55s as calibration, and leave retraction latency unnamed. Site 2's new bound is an inequality with a hole in it. Site 3 will go green on a tautology if the replacement invariant does not pin: hangup retention ≥ ring window + delivery bound, ceiling (best-effort) ≤ that same window, and Swift/Dart cannot restart from delivery time. The 2026-08-15 warning ("conflating staleness with ring duration is how you ring for a call that already ended") is not shown to hold; it is scheduled to be replaced in the same commit. That is a hope, not a design.

- **Foreground and push-woken admission order (§3 arm b, Open questions).** If in-app WS delivery still admits-then-rings while VoIP rings-then-admits, mute "works" in testing and fails on a locked phone. Arm (b) ("delete Dart's timer") does not make them the same path. One Swift provider, two admission orders, is the mute regression arriving as a platform split rather than a product call.

- **VoIP token lifetime versus Decision 2a (§5, §7).** A VoIP token that exists before dual-kind unregister is real *is* the stranger-ringing-for-the-previous-owner state. Sequencing "against #3723" is a preference. The invariant is: no PushKit registration, no `.voip` row, until a sign-out cannot leave a live VoIP token. Partial debt is the default (Design 12 Decision 2). Treat that as a gate, not a later cage-match.

- **`noServerId` versus client-minted ULID (Design 16 §4 table vs Design 12 Decision 1).** Nine start gates still include a refusal whose object (island server id as the only name a hangup can carry) is being replaced. `_ended` re-bind in §1 Site 2 changes the *duration* and not the *key*. If hangups name ULIDs and admit still demands `noServerId`, you refuse living calls or retain ends you can never match.

- Site 2: hangup GC at `freshness × 2` while a ring can outlive it is the inverted failure arriving through our own retention. The diagnosis is correct even if the new bound is unfinished.
- Site 3: the test group `'the two clocks are different numbers'` will be deleted by a green-suite coward unless the liveness invariant lands in the same commit. That trap is real.
- Freshness keyed off `signedAtMs` and a signed end, never island `createdAt`. The island gains no new *stated* authority. (It gains unstated authority via payload clocks and UUID; that is the recast, not a retraction of this constraint.)
- Decision 2a, `PendingUnregisterStore` without kind, permission asymmetry as a normal state, `#3723` as the drain that covers both kinds by construction.

- `#3588` narrowing: CallKit has no notification tap; the alert path keeps the bug. Correct.
- Disagreements with design 12 marked rather than folded. Keep that discipline, then mark the ones you missed (payload opacity vs on-device proof; Decision 1c "taken" vs a fork of two unsound timers).

**If RECAST, what to fold back:**

- **Replace the one-sentence version.** The client's job does not change from "whether to ring" to "how fast to stop." The PushKit handler is the admit site. Dart is the cache writer and the in-app client of a Swift `CXProvider`. Ring-then-retract is the Apple-compliance path for *failed* admit, not the architecture for successful ones.
- **Write the handler contract as a closed table, in this repo, with Design 12's payload recast attached if the table needs bytes it does not have:**
  - invite VoIP → Swift admit (signature + window + local mute/block/consent + `_ended`) → `reportNewIncomingCall` on the *signed* ULID-as-UUID, or report-and-end in the same handler if admit fails
  - end VoIP → `reportCall(endedAt:)` on that UUID, never a new incoming; state what Apple call satisfies "reported"
  - unknown / unparseable → report-and-end, placeholder name, not Recents if the API allows per-call exclusion
  - every branch talks to CallKit before return
- **Mark the payload disagreement with Design 12 Decision 6.** Either the VoIP payload carries the signed origin envelope (size-bounded, visibility re-priced), or on-device proof is impossible and island `should_wake` is the real admit — in which case §4's "must be argued" is decided, and `call_invite.dart:441`'s spirit is broken for the loudest privilege. Do not ship a third state where both documents believe the other holds the proof.
- **Retire Decision 1c as "taken."** Record: no in-process timer, Dart or Swift, re-establishes a 30s ceiling under suspension. Best-effort `beginBackgroundTask` is named as best-effort. The signed end-push is the stop that survives. The dead-caller residual is unbounded until user/OS. That premise-shift belongs on the gathering-design record, which is why 1c existed.
- **Make Answer a first-class state.** `CXAnswerCallAction` cannot be fulfilled until Swift-admit has passed, or it is fulfilled into a defined "connecting / dropped" UX if the OS forces fulfill-before-engine. "Stop" is specified separately for ringing vs answered.
- **Bind one identity.** CallKit UUID = signed v2 ULID. Payload UUID is untrusted until it matches. `_ended` keys by that ULID. `noServerId` is re-justified or deleted in the same breath as v2.
- **Name cache is caller-ID.** Cached display name is applied only after admit. Failed admit uses `Aiko` (already decided) and must not write Recents as a missed call from a real person. Revisit `includesCallsInRecents = true` under ring-then-retract; the ruling was for calls the user was party to.
- **`kPushDeliverySlack` is derived or deleted.** One inequality, one test replacing Site 3: retention ≥ ring window + `apns-expiration`; liveness window is that same ring window from `signedAtMs`; delivery time never restarts it. 17.55s calibrates the window's lower bound, not a fourth constant.
- **No VoIP token until dual unregister is real.** `#3723` (or an equivalent that cannot leave a `.voip` row after sign-out) is a gate on PushKit registration, not a sequence note next to §5.
- **One admission order.** In-app and push-woken enter the same Swift provider after the same admit predicate. If a gate cannot run in Swift, it is not a start-gate on the CallKit path; it is a retract-gate, and the settings copy says so.
- **Do not start §7 step 1 as if it were safe under every arm.** Site 2/3 are correct hygiene. They are not permission to build toward an unchosen trust boundary. Close §4 (including the Swift-admit arm) and the handler table first; the rest is implementation of that table.

The ore is not slag. The ringing-as-message thesis, the enum of nine, the hangup that must outlive the sound — those hum at the right frequency. What shatters is the story that Dart's absence is the design. Dart is a delayed witness. Swift is the circuit. Until the client half is a handler and a UUID map, this document is a brilliant briefing of the blast, not the Faraday cage around it.
