## MaxwellMergeSlam's Design Strike

**Verdict:** RECAST

**Summary:** The design's headline finding is real, but it built its own false binary around it and its liveness predicate evaporates in exactly the case CallKit exists for — `John McClane: "Welcome to the party, pal."`

**Fatal flaws:**

- **§4 — WRONG OPTION-FRAME, and it is the author's own.** The doc frames the signature
  problem as two arms: ring before proof, or move proof to the island. **There is a third and
  the doc never names it: verify in Swift.** Ed25519 verification is CryptoKit
  (`Curve25519.Signing.PublicKey.isValidSignature`) and takes microseconds; the VoIP payload
  can carry the signed bytes; and **§6 of this very document already establishes a
  Swift-readable cache** that Dart maintains — the exact place a sender's public key would
  live. The design conflated *"Dart does not exist yet"* with *"verification cannot happen
  yet"*, which is a claim about a runtime smuggled in as a claim about a capability. The
  arm that best preserves the product's thesis was excluded by an unexamined premise, and
  then the doc built a trust-boundary crisis on top of the exclusion.
  Sharpen, don't delete: Apple requires a report per VoIP push, so the honest arm is
  *verify → report → immediately end if invalid*, inside one handler, rather than
  *ring → boot Dart → retract*. That is a materially different failure (a report that may
  never draw UI vs seconds of audible ringing) and the doc owes the distinction.

- **§2 — MISSING FAILURE MODE: the liveness object is not there on a cold start.** The design
  argues freshness is a proxy and *"the object already exists"* — a signed end, held in
  `RingController._ended`. That map is **in-memory Dart state**. On a push-woken cold start
  — the case this entire design exists for — it is empty by construction, and the end may
  already be sitting in island history, retrievable only by a REST fetch, which is precisely
  the latency CallKit forbids. So §2's predicate degenerates on the cold path to *the window
  alone*, which is the thing §2 claims to be replacing. **The half of the liveness signal we
  hold is the half that does not survive termination.** Either the end must be durable
  (and readable from Swift, which drags it into §6's cache), or §2 must state plainly that
  liveness is window-only on cold start and re-argue the window on that basis.

- **§1 + §7 — the sequencing claim contradicts the design's own open question.** §7 says
  item 1 (`_ended` retention + the pinned invariant) is *"the only part that is safe to do
  before the fork in §4 is decided, because it is correct under every arm."* But the new
  bound is `kCallRingDuration + kPushDeliverySlack`, and the Open Questions section concedes
  `kPushDeliverySlack` *"has no value and no derivation."* A step is not safe-to-start when
  its central quantity is admitted-unknown three headings later. Naming an unearned constant
  honestly does not discharge it.

- **§3 — a preference stated ahead of the check that would test it.** The doc prefers arm (b)
  (delete the Dart timer, Swift owns the ceiling outright) while listing *"the in-app ring
  path under arm (b) is unexamined"* as an open question. Arm (b)'s single plausible
  objection is the thing left unexamined, so the preference is a coin-flip wearing a
  rationale. Either examine it or drop to no-preference.

**What holds:**

- **The core finding survives and is the reason to keep the document.** The refusals *do* all
  become post-hoc, the enum genuinely carries nine start-gates where the prose named five,
  and `unverifiedOrigin` genuinely heads the list. Enumerating from the enum rather than the
  doc comment is the move that produced the finding.
- **§1's three-sites census is correct and is the kind of thing only a repo-local reader
  finds.** The `_ended` retention bound (`freshness * 2`) is a real second consumer that the
  peer record could not see, and the "phone rings for a corpse because we forgot the stop"
  failure follows from it.
- **The refusal to hand the island the freshness decision** (`call_invite.dart:441`) is
  correctly identified as the constraint to answer rather than step around, and §2 does
  answer it rather than quietly relaxing it.
- **Honest scoping in the provenance block** — the doc states which claims are inherited from
  the peer record and unverified by this tab. That is the right disclosure and it is what let
  the SDK-version discrepancy surface separately.

**If RECAST, what to fold back:**

- Add a fourth arm to §4: **Swift-native Ed25519 verification before the CallKit report**,
  with its real cost (public key must reach the Swift cache, so §6's cache grows from names
  to keys — a bigger plaintext artifact, which #3695 must then price) and its real
  constraint (a report is mandatory per push; the arm is verify-report-end, not verify-or-
  silence). Re-rank the other three arms against it.
- Rewrite §2 to distinguish **warm-path liveness** (the `_ended` map is live; the predicate
  works as described) from **cold-start liveness** (the map is empty; the predicate is
  window-only). State which one the design is actually claiming, and if durable end-storage
  is required, say so as a component rather than an assumption.
- Move §7 item 1 behind the derivation of `kPushDeliverySlack`, or re-scope it to the pinned
  invariant only (which genuinely is arm-independent) and leave the retention bound with the
  fork.
- Drop §3's stated preference to no-preference until the in-app path is examined.
